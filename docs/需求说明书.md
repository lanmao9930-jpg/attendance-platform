# 就业服务团值班考勤平台需求说明书

## 1. 项目目标

用一个统一平台替代腾讯文档的签到签退收集与行政手工汇总。学生只做扫码、填表和上传值班照片；行政事务中心在独立的受保护管理端完成排班归档、考勤审核、照片核验和导出。

本文件是本项目后续修改的唯一需求基线。任何新增页面、字段或功能不得让学生看到管理数据，不得重新引入需要逐位同学手工核对和填表的流程。

## 2. 角色与权限

| 角色 | 入口 | 可见内容 | 不可见内容 |
| --- | --- | --- | --- |
| 现场设备 | `/display?key=现场屏密钥` | 动态二维码 | 后台、排班、统计、原始记录、导出 |
| 学生 | 扫码后的 `/student?token=...` | 本人本次签到/签退表单 | 后台、他人数据、考勤状态、排班、原始记录 |
| 管理员 | `/admin` + 管理员口令 | 二维码、固定排班、审核、原始归档、导出 | 无 |

根地址 `/` 只跳转现场二维码页，不提供管理端入口。管理员地址通过管理群或管理员书签单独分发。

## 3. 学生端表单

学生扫码后必须且只能填写以下字段：

1. 姓名
2. 所在中心：主席团、精英团、行政事务中心、大数据中心、市场拓展中心、视频运营中心、宣讲招聘中心、培训中心、职研中心、青创中心、新媒体中心
3. 职位：学生助理、副主管、主管、副团长、团长、实习生
4. 值班类型：正常、调班。选择“调班”后必须填写调班说明，至少说明原值班时间、实际值班时间及调班对象或原因
5. 值班时间：服务器按北京时间显示当天日期、星期和学期周次，学生不可自行修改；节次支持多选，同一名同学连续值班时可同时选择两个或多个节次
6. 本次类别：签到、签退
7. 值班照片：必须上传一张 JPG、PNG 或 WebP；手机优先调用相机，浏览器会压缩后上传。照片读取与解码须有超时和明确错误；压缩失败但原图格式可识别且不超过 2 MB 时直接上传原图。无法处理的大图提示重拍，不得出现空白错误或丢失已填写内容。提交错误在按钮附近展示。

学生选择的“正常、调班”只表示本次值班类型，不代表可以修改最终考勤结论。学生不能自行填写“请假、迟到、缺勤”等考勤状态，也不能查看任何汇总或原始数据。

## 4. 管理端流程

1. 行政上传 Excel/CSV 或粘贴数据后，系统识别中心并预览“新增/更新”和前后条数，统一使用“按中心导入当前学期”。尚未导入的中心新增，已有中心按本次文件修订，其他中心保留。每次修改前保存排班和审核快照，可在“导入记录”查看。
2. 现场设备始终打开二维码页；学生扫码完成签到或签退。
3. 系统将每次提交原样归档，保存时间、表单字段和照片。
4. 系统按“姓名 + 中心 + 实际周次 + 星期 + 节次”将正常签到和签退自动匹配到当前固定排班；一次提交选择多个节次时，每个节次分别匹配一条固定排班并形成独立考勤结果，不能因为其中一个节次匹配成功就忽略其余节次。周期排班会先判断实际周次是否符合每周、单周、双周或指定范围规则。学生申报调班时，系统根据姓名、中心、周次、实际时间和调班说明关联其原排班；一次调班覆盖多个实际节次时，应按节次数量关联相应数量的原排班。能关联的直接记为“调班”并保留学生说明，不强制标红复核。
5. 管理员在“考勤审核”检查系统初判。正常、迟到和已关联的学生调班申报直接自动归档；填写与排班不一致、调班无法关联、缺少记录或签退异常的人员醒目标红，再由主管人工确认正常、调班、请假、迟到或缺勤。管理员选择“调班”时备注必填，用于记录具体调班情况。
6. 管理员可按周次和中心筛选考勤审核数据，避免一次浏览全团数百条记录。
7. 管理员从“原始归档”查看每次提交和受保护照片；从“导出考勤汇总”导出结果。

## 5. 固定排班导入格式

管理端优先支持直接上传 `.xlsx`、`.xls`、`.csv` 文件，单个文件不超过 4 MB。系统扫描文件内所有工作表，自动寻找表头；文件只要含有任意一个可识别中心的有效人员安排即可预览和导入，不要求每个中心都有工作表或数据。中心名称既可逐行填写，也可写在工作表名称或标题中。粘贴制表符分列数据只作为备用入口。

上传后先显示识别到的固定排班、值班同学数量、排班次数不是两次的人数、未导入行及原因；管理员点击确认前不保存或覆盖正式排班。推荐字段为：

`中心 | 周次 | 星期 | 节次 | 值班人员 | 职位 | 联系电话`

系统识别下列常用表头：`中心/所在中心`、`周次/周数`、`星期/周几`、`节次/时间段/值班时间`、`值班人员/姓名/人员名单`、`职位/职务`、`联系电话/电话/手机号`。

“值班时间”可以是一个组合字段，例如 `第4周 周四 7-8节`，系统会自动拆分为周次、星期和节次。中心简称如“行政中心”会归一为“行政事务中心”；无法识别的行必须明确指出所在工作表、行号和缺失字段，不得只返回笼统的“中心名称不明确”。

系统还必须识别常见的横向课表：星期位于列标题，`1-2、3-4、5-6、7-8` 节位于行标题，交叉单元格内填写一名或多名同学。工作表名如“行政事务中心”即为该表中心；合并单元格、换行、空格、中文逗号和多名同学不得导致漏读。标题或姓名备注中的“每周、单周、双周、6周以前、8周后、每月第1至第4周”等内容应保存为周期规则，管理员在考勤审核中按实际周次切换查看。

日常导入仅更新本次文件中的中心，默认不得创建全新批次或覆盖全团。重新导入同一中心时，文件代表该中心完整的新排班；未变化的排班保留记录标识及审核关联。导入采用数据版本检查，预览后其他管理员修改数据则拒绝过期提交，要求重新预览。无效中心和排班字段阻止保存，完全重复行去重。

“开启新学期”独立放在“学期日历”页面，需要输入新的学期名称、第一周星期一日期并确认归档。该操作保留旧学期排班、考勤和快照，新学期从空排班开始，之后逐中心导入。
导入完成后，系统会提示排班次数不是两次的同学数量，供行政在开始考勤前核对；提示不阻断导入，便于处理已获批的例外情况。

## 6. 考勤状态规则

### 学期日历

- 本学期为 2026 年秋季，第一周从 2026-09-07 星期一开始；9月7日至13日为第一周，9月14日至20日为第二周。
- 业务时间统一采用服务器时间和 Asia/Shanghai 时区；周次不随文件导入日期、学生设备日期或学生填写字段变化。
- 周次按每周一零时递增，跨月和跨年连续计算；法定假期不会自动重置或暂停周数。
- 开学前显示“学期尚未开始”，学期结束后显示“本学期已结束”，这两个阶段不接收正式扫码提交；暂沿用星期一至五的值班范围。
- 管理员可保存学期日历；已有本学期正式考勤后，不允许改写起始日期或周数，避免重算历史。换学期使用独立的开启新学期操作。
- 管理端默认查看实际当前周，周次选项显示日期范围；审核和导出包含具体值班日期。未到开始时间显示“未开始”，值班中未签到显示“待签到”，结束仍无记录再进入待核查。
- 学生选择的节次继续支持多选。后台以提交时刻重新计算日期；跨日旧表单需重新扫码。

值班时间统一按中国标准时间判断：

| 节次 | 开始时间 | 结束及签退时间 |
| --- | --- | --- |
| 一二节 | 08:30 | 10:10 |
| 三四节 | 10:30 | 12:10 |
| 五六节 | 14:30 | 16:10 |
| 七八节 | 16:30 | 18:10 |

系统初判规则：

| 系统状态 | 自动产生方式 | 是否需要主管处理 |
| --- | --- | --- |
| 正常 | 签到时间不晚于对应节次开始时间 | 否；未到结束时间时显示“待签退” |
| 迟到 | 签到时间晚于对应节次开始时间，不设置额外宽限分钟 | 否；仍需在结束时间签退 |
| 调班 | 学生选择调班、填写具体说明，且系统能关联本人当前固定排班 | 否；保留为可选人工修正，不强制标红 |
| 异常 | 只签退没有签到、签退早于结束时间、已过结束时间仍未签退，或姓名/中心/周次/星期/节次与固定排班不一致 | 是；整行标红并说明不一致字段 |
| 待核查 | 固定排班没有找到任何匹配的签到或签退 | 是；主管确认缺勤、调班、请假或填写错误 |

一次提交多选节次时，系统按每个节次各自的开始和结束时间分别判断。例如同时选择“五六节、七八节”，一次签到和一次签退可完成两条固定排班；任一节次无法匹配时，只将该节次列为异常，不影响已正确匹配的节次。

人工复核最终状态为“正常、调班、请假、迟到、缺勤”五种。管理员保存的人工状态和备注优先于系统初判，并同时保留原系统判断依据；管理员人工改为调班时必须写明具体情况。学生不能看到或自行修改最终考勤状态。

## 7. 数据与隐私要求

- 线上正式环境使用腾讯云 CloudBase 文档数据库保存排班、签到签退和审核记录，使用 CloudBase 云存储保存值班照片。
- 签到照片存为私有文件，只能通过已登录的管理员管理端访问。
- 管理员口令和二维码签名密钥只放在 CloudBase 云函数环境变量中，不写入代码、不发给学生；现场屏密钥由签名密钥派生，只通过管理员后台生成现场屏地址。
- 动态二维码 5 秒更换；扫码后表单会话 3 分钟有效，兼顾现场扫码和填写时间。

## 8. 验收标准

1. 现场屏和学生端没有任何后台导航、看板、排班、原始记录或导出入口。
2. 扫码能进入并提交含照片的表单；未扫码直接打开学生页不能提交。
3. 管理端未登录不能读取排班、审核、原始记录、照片或导出。
4. 上传 Excel/CSV 和粘贴入口均按中心合并。验收顺序：导行政、导大数据、重新导行政，最后两个中心都存在且仅行政被更新；修改前快照仍可查看。日常入口拒绝整批替换，开启新学期独立操作。
5. 签到提交后按四个节次开始时间自动形成正常或迟到；学生可一次多选连续节次，后台分别匹配并生成多条排班考勤结果，部分节次不匹配时只标记未匹配部分；学生申报调班并填写说明后自动归档为调班；提前签退、缺少记录和排班字段不一致显示异常或待核查并标红；人工复核可选择请假。
6. 刷新或重新部署后，已导入排班、签到记录、审核状态和照片仍保存在 CloudBase 中。

## 9. 明确不做

- 不让学生登录管理端，不向学生公开任何全团考勤数据。
- 不保留原 Excel 中“原排班情况”这一需要再次人工填写的列。
- 不把真实成员姓名、电话或默认排班写死在代码中。
- 不以腾讯文档作为正式考勤数据源；腾讯文档可在过渡期保留，但不再是最终归档。
